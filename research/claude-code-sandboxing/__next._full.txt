data-article-body="true" data-theme="ivory"><p class="PA4F1q_reading-column post-text">In <a id="base-ui-_R_3s1drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://www.claude.com/product/claude-code" rel="noopener noreferrer">Claude Code</a>, Claude writes, tests, and debugs code alongside you, navigating your codebase, editing multiple files, and running commands to verify its work. Giving Claude this much access to your codebase and files can introduce risks, especially in the case of prompt injection.</p><p class="PA4F1q_reading-column post-text">To help address this, we’ve introduced two new features in Claude Code built on top of sandboxing, both of which are designed to provide a more secure place for developers to work, while also allowing Claude to run more autonomously and with fewer permission prompts. In our internal usage, we've found that sandboxing safely reduces permission prompts by 84%. By defining set boundaries within which Claude can work freely, they increase security and agency.</p><h2 class="tOQyXa_headline-4 PA4F1q_reading-column post-heading" data-component="Headline" id="keeping-users-secure-on-claude-code">Keeping users secure on Claude Code</h2><p class="PA4F1q_reading-column post-text">Claude Code runs on a permission-based model: by default, it's read-only, which means it asks for permission before making modifications or running any commands. There are some exceptions to this: we auto-allow safe commands like echo or cat, but most operations still need explicit approval.</p><p class="PA4F1q_reading-column post-text">Constantly clicking "approve" slows down development cycles and can lead to ‘approval fatigue’, where users might not pay close attention to what they're approving, and in turn making development less safe.</p><p class="PA4F1q_reading-column post-text">To address this, we launched sandboxing for Claude Code.</p><h2 class="tOQyXa_headline-4 PA4F1q_reading-column post-heading" data-component="Headline" id="sandboxing-a-safer-and-more-autonomous-approach">Sandboxing: a safer and more autonomous approach</h2><p class="PA4F1q_reading-column post-text">Sandboxing creates pre-defined boundaries within which Claude can work more freely, instead of asking for permission for each action. With sandboxing enabled, you get drastically fewer permission prompts and increased safety.</p><p class="PA4F1q_reading-column post-text">Our approach to sandboxing is built on top of operating system-level features to enable two boundaries:</p><ol class="PA4F1q_reading-column text-body-1-serif post-text"><li><strong>Filesystem isolation</strong>,<strong> </strong>which ensures that Claude can only access or modify specific directories. This is particularly important in preventing a prompt-injected Claude from modifying sensitive system files.</li><li><strong>Network isolation</strong>,<strong> </strong>which ensures that Claude can only connect to approved servers. This prevents a prompt-injected Claude from leaking sensitive information or downloading malware.</li></ol><p class="PA4F1q_reading-column post-text">It is worth noting that effective sandboxing requires <em>both</em> filesystem and network isolation. Without network isolation, a compromised agent could exfiltrate sensitive files like SSH keys; without filesystem isolation, a compromised agent could easily escape the sandbox and gain network access. It’s by using both techniques that we can provide a safer and faster agentic experience for Claude Code users.</p><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="two-new-sandboxing-features-in-claude-code">Two new sandboxing features in Claude Code</h3><h4 class="tOQyXa_headline-6 PA4F1q_reading-column post-subsection" data-component="Headline" id="sandboxed-bash-tool-safe-bash-execution-without-permission-prompts">Sandboxed bash tool: safe bash execution without permission prompts</h4><p class="PA4F1q_reading-column post-text">We're introducing <a id="base-ui-_R_7kedrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://docs.claude.com/en/docs/claude-code/sandboxing" rel="noopener noreferrer">a new sandbox runtime</a>, available in beta as a research preview, that lets you define exactly which directories and network hosts your agent can access, without the overhead of spinning up and managing a container. This can be used to sandbox arbitrary processes, agents and MCP servers. It is also available as <a id="base-ui-_R_7oedrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://github.com/anthropic-experimental/sandbox-runtime" rel="noopener noreferrer">an open source research preview</a>.</p><p class="PA4F1q_reading-column post-text">In Claude Code, we use this runtime to sandbox the bash tool, which allows Claude to run commands within the defined limits you set. Inside the safe sandbox, Claude can run more autonomously and safely execute commands without permission prompts. If Claude tries to access something <em>outside</em> of the sandbox, you'll be notified immediately, and can choose whether or not to allow it.</p><p class="PA4F1q_reading-column post-text">We’ve built this on top of OS level primitives such as <a id="base-ui-_R_3sgdrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://github.com/containers/bubblewrap" rel="noopener noreferrer">Linux bubblewrap</a> and MacOS seatbelt to enforce these restrictions at the OS level. They cover not just Claude Code's direct interactions, but also any scripts, programs, or subprocesses that are spawned by the command.As described above, this sandbox enforces both:</p><ol class="PA4F1q_reading-column text-body-1-serif post-text"><li><strong>Filesystem isolation, </strong>by allowing read and write access to the current working directory, but blocking the modification of any files outside of it.</li><li><strong>Network isolation, </strong>by only allowing internet access through a unix domain socket connected to a proxy server running outside the sandbox. This proxy server enforces restrictions on the domains that a process can connect to, and handles user confirmation for newly requested domains. And if you’d like further-increased security, we also support customizing this proxy to enforce arbitrary rules on outgoing traffic.</li></ol><p class="PA4F1q_reading-column post-text">Both components are configurable: you can easily choose to allow or disallow specific file paths or domains.</p><div class="PA4F1q_media-column" data-type="image"><figure class="Duq99q_e-imageWithCaption"><img alt="This image illustrations how sandboxing in Claude Code works." loading="lazy" width="4096" height="2305" decoding="async" data-nimg="1" style="color:transparent" src="https://origin-ten-jet.vercel.app/sites/anthropic/pages-assets/92a33f72cdd81f4f7c33.webp"><figcaption class="RMuY0W_root -LJkNq_container -LJkNq_container--default" data-component="RichTextWrapper"><div class="tOQyXa_caption-1 -LJkNq_text" data-component="Caption">Claude Code's sandboxing architecture isolates code execution with filesystem and network controls, automatically allowing safe operations, blocking malicious ones, and asking permission only when needed.</div></figcaption></figure></div><p class="PA4F1q_reading-column post-text">Sandboxing ensures that even a successful prompt injection is fully isolated, and cannot impact overall user security. This way, a compromised Claude Code can't steal your SSH keys, or phone home to an attacker's server.</p><p class="PA4F1q_reading-column post-text">To get started with this feature, run /sandbox in Claude Code and check out <a id="base-ui-_R_3sldrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://docs.claude.com/en/docs/claude-code/sandboxing" rel="noopener noreferrer">more technical details</a> about our security model.</p><p class="PA4F1q_reading-column post-text">To make it easier for other teams to build safer agents, we have <a id="base-ui-_R_3smdrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://github.com/anthropic-experimental/sandbox-runtime" rel="noopener noreferrer">open sourced</a> this feature. We believe that others should consider adopting this technology for their own agents in order to enhance the security posture of their agents.</p><h4 class="tOQyXa_headline-6 PA4F1q_reading-column post-subsection" data-component="Headline" id="claude-code-on-the-web-running-claude-code-securely-in-the-cloud">Claude Code on the web: running Claude Code securely in the cloud</h4><p class="PA4F1q_reading-column post-text">Today, we're also releasing <a id="base-ui-_R_3sodrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://docs.claude.com/en/docs/claude-code/claude-code-on-the-web">Claude Code on the web</a> enabling users to run Claude Code in an isolated sandbox in the cloud. Claude Code on the web executes each Claude Code session in an isolated sandbox where it has full access to its server in a safe and secure way. We've designed this sandbox to ensure that sensitive credentials (such as git credentials or signing keys) are never inside the sandbox with Claude Code. This way, even if the code running in the sandbox is compromised, the user is kept safe from further harm.</p><p class="PA4F1q_reading-column post-text">Claude Code on the web uses a custom proxy service that transparently handles all git interactions. Inside the sandbox, the git client authenticates to this service with a custom-built scoped credential. The proxy verifies this credential and the contents of the git interaction (e.g. ensuring it is only pushing to the configured branch), then attaches the right authentication token before sending the request to GitHub.</p><div class="PA4F1q_media-column" data-type="image"><figure class="Duq99q_e-imageWithCaption"><img alt="This illustration depicts how Claude Code on the web uses a custom proxy to
