class="PA4F1q_reading-column post-text">Søren Kierkegaard wrote that life can only be understood <em>backward</em>, but it must be lived <em>forward</em>. We’ve encountered a similar bind when designing memory for AI agents.</p><p class="PA4F1q_reading-column post-text">As humans, we encode memory constantly as we go about our lives. <a href="https://stanford.edu/~jlmcc/papers/McCMcNaughtonOReilly95.pdf">The hippocampus</a> plays a central role in this, capturing experiences in the moment so that memories form quickly and are immediately available. But only <a id="base-ui-_R_fg2drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://www.science.org/doi/10.1126/science.adk8261?referrer=https%3A%2F%2Fwww.google.com%2F">some experiences</a> are consolidated into long-term knowledge.</p><p class="PA4F1q_reading-column post-text">Much of that consolidation appears to happen when our brains are offline. As we sleep, and during quiet <a id="base-ui-_R_f83drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://www.nature.com/articles/s41467-018-06213-1">rest</a>, the hippocampus replays our recent experiences. This is thought to gradually distill <a id="base-ui-_R_fg3drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://www.nature.com/articles/s41593-019-0467-3">those experiences and integrate them</a> into the neocortex—the part of our brains that stores most of what we think of as knowledge.</p><p class="PA4F1q_reading-column post-text">Agent memory can use a similar division of labor. Agents capture much of their work in logs or transcripts. Researchers at Letta and UC Berkeley proposed <a id="base-ui-_R_f84drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://arxiv.org/abs/2504.13171">sleep-time compute</a> as a way for models to use idle time between interactions to reorganize their existing context. The same idea can help agents organize their memory by reflecting on logs to fix mistakes or produce new notes and representations. This process is often <a id="base-ui-_R_fg4drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://platform.claude.com/docs/en/managed-agents/dreams">called</a> <a id="base-ui-_R_fo4drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://research.google/blog/the-sleep-framework-a-new-way-for-llms-to-retain-knowledge-in-continual-learning/"><em>dreaming</em></a> (Figure 1).</p><p class="PA4F1q_reading-column post-text">We’ve found that dreaming has been a useful tool for helping us give Claude effective memory. In this post, we share how we’ve come to think about agent memory and walk through several evaluations we’ve used to explore agent memory, including the use of dreaming, and what each component contributes to memory organization.</p><div class="PA4F1q_media-column" data-type="image" data-width="full-width"><figure class="Duq99q_e-imageWithCaption"><img alt="Diagram of a memory hierarchy between one session and the next. This can correct mistakes, create notes, build new memory representations, or shape what’s preemptively loaded into future sessions.</div></figcaption></figure></div><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="memory-notes">Memory notes</h3><p class="PA4F1q_reading-column post-text">By “agent memory,” we mean knowledge that Claude gains from experience—including interactions with users and tasks it’s been assigned—and that it retains between sessions, saved as context it can read later. It excludes other ways models can learn or manage context, such as changes to their <em>weights</em> (the internal parameters set during training), <a href="/research/in-context-learning-and-induction-heads"><em>in-context learning</em></a> (knowledge gained within a single conversation), and <a id="base-ui-_R_fo8drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://platform.claude.com/docs/en/build-with-claude/compaction"><em>compaction</em></a> (summaries written by Claude that replace its older turns so it can continue working in a new context window).</p><p class="PA4F1q_reading-column post-text">In the human brain, chemical signals released before, during, or after an experience can <a id="base-ui-_R_f89drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://www.nature.com/articles/385533a0">mark a memory</a> as important. Marked memories tend to be replayed more often than unmarked ones during offline periods. This process, called <em>replay</em>, helps stabilize and integrate them into long-term memory.</p><p class="PA4F1q_reading-column post-text">Similarly, Claude can tag salient events in a session log as they happen, so they’re easier to find later, or it can <a id="base-ui-_R_7oadrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool">write</a> them to a memory store, such as a folder of memory notes (Figure 2). But how can Claude tell what’s salient in the moment, before it knows what’s coming next?</p><div class="PA4F1q_media-column" data-type="image" data-width="full-width"><figure class="Duq99q_e-imageWithCaption"><img alt="The same memory hierarchy, with the memory notes layer highlighted. An arrow runs from the session directly to the memory notes, described as salient observations written by Claude." loading="lazy" width="3840" height="1754" decoding="async" data-nimg="1" style="color:transparent" src="https://origin-ten-jet.vercel.app/sites/anthropic/pages-assets/51a53c4610ddddb56380.webp"><figcaption style="--figure-label:&quot;Figure 2&quot;" class="RMuY0W_root -LJkNq_container -LJkNq_container--default" data-component="RichTextWrapper"><div class="tOQyXa_caption-1 -LJkNq_text" data-component="Caption">Claude can write notes to memory.</div></figcaption></figure></div><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="memory-can-be-a-prediction-about-what-the-future-will-need">Memory can be a prediction about what the future will need</h3><p class="PA4F1q_reading-column post-text">Memory is, occasionally, a prediction. By writing down a rule, an agent predicts that the pattern it’s describing will be relevant again. For instance, writing down a verified fact is a prediction that an agent in a future session will want to rely on that fact without double-checking it. Over time, Claude has become much better at making these kinds of predictions.</p><p class="PA4F1q_reading-column post-text">Consider a task from <a id="base-ui-_R_7oedrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://continual-learning-bench.com/news/cl-bench-1-0/">Continual Learning Bench (CL-Bench) 1.0</a>, a benchmark that measures an agent’s ability to use memory in order to tackle long-horizon tasks. One particular task asks Claude to answer a series of questions by looking up information in a database. After Claude gives an answer, it’s told the correct solution and can write a memory to help answer future questions.</p><p class="PA4F1q_reading-column post-text">Memory can support a learning loop here. If Claude gets a question wrong, it can record the failure, come up with theories about what went wrong, test those theories, and turn what it finds into a rule about how to answer in the future.</p><p class="PA4F1q_reading-column post-text">We ran the CL-Bench 1.0 task using <a id="base-ui-_R_f8gdrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://platform.claude.com/docs/en/managed-agents/overview">Claude Managed Agents</a>. Injected context is loaded into every session, and the layers below it are read or searched when Claude needs them.</div></figcaption></figure></div><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="dreaming-can-focus-memory-on-a-specific-goal">Dreaming can focus memory on a specific goal</h3><p class="PA4F1q_reading-column post-text">Dreaming can also shape how memory grows. An assistant like <a id="base-ui-_R_7q2drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://support.claude.com/en/articles/17631495-get-started-with-claude-duet">Claude Duet</a>, for example, often benefits from having memories that are organized around the person it’s helping, and dreaming can be tuned to build memory in service of a particular goal.</p><p class="PA4F1q_reading-column post-text">The instructions that guide how memory grows differ by task and tell Claude what information actually matters. For example, one task in the LAB benchmark simulates a company acquisition and provides a set of contracts. The brief is graded on whether it correctly describes the contract terms.</p><p class="PA4F1q_reading-column post-text">We started with basic instructions for generating the wiki that didn’t tell Claude <em>how</em> to use the wiki. This task relied heavily on contract terms. While the wiki was being built, several agents wrote to a shared table of contract terms at the same time (Figure 14, left).</p><div class="PA4F1q_media-column" data-type="image" data-width="full-width"><figure class="Duq99q_e-imageWithCaption"><img alt="Two diagrams. Before: four agents write to the same shared page, provisions.md, and one agent’s save erases another’s lines; 41 of 57 graded facts survived. After: four agents each write their own contract’s page, with terms copied word for word; all 57 of 57 graded facts survived." loading="lazy" width="3840" height="1822" decoding="async" data-nimg="1" style="color:transparent" src="https://origin-ten-jet.vercel.app/sites/anthropic/pages-assets/9b2a7cee1b356e4da696.webp"><figcaption style="--figure-label:&quot;Figure 14&quot;" class="RMuY0W_root -LJkNq_container -LJkNq_container--default" data-component="RichTextWrapper"><div class="tOQyXa_caption-1 -LJkNq_text" data-component="Caption">How many graded contract facts made it into the wiki, before and after instructions changed. Left: several agents writing to one shared page; 41 of 57 facts survived. Right: one agent per contract, each writing its own page and quoting terms word for word; 57 of 57 facts survived.</div></figcaption></figure></div><p class="PA4F1q_reading-column post-text">The result was a wiki that was missing key facts. When we graded a brief generated from the wiki, Claude had included only 41 of the 57 facts (72%). When we looked at what had gone wrong, we found that the shared table summarized the contract terms poorly and was missing some of them altogether, because agents had overwritten one another’s work.</p><p class="PA4F1q_reading-column post-text">The contract terms were the most important part of the wiki, but the instructions didn’t say that. To find better instructions, we ran a loop in which Claude reflected on its failures, proposed a change to the instructions, and rebuilt the wiki. This loop allowed Claude to discover how important it was to follow the contract terms, and it rewrote the instructions for building the wiki accordingly.</p><p class="PA4F1q_reading-column post-text">Each contract got its own page in the wiki, written by a single agent, which quoted the terms word for word rather than summarizing them into a shared table. When we graded the brief generated from this improved wiki, 100% of the criteria could be met, up from 72%.</p><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="dreaming-can-fill-in-gaps-a-session-leaves-behind">Dreaming can fill in gaps a session leaves behind</h3><p class="PA4F1q_reading-column post-text">When Claude writes memory notes, it sees only the context in <em>that</em> particular session. Dreaming can search across many sessions to find common patterns or correct common mistakes.</p><p class="PA4F1q_reading-column post-text">When building the wikis for the LAB benchmark (as an example, see Figure 14), sometimes Claude would link to pages that hadn’t yet been created. A second dreaming pass closed many of these gaps. On one task (Figure 15), dreaming found nine links to a missing page in the wiki and repointed them to an existing page for the same document. It also added three new pages, including an index, to improve the wiki.</p><div class="PA4F1q_media-column" data-type="image" data-width="full-width"><figure class="Duq99q_e-imageWithCaption"><img alt="Two network graphs of a wiki. Before the second pass: 38 entries and 225 links, with nine links from six pages pointing to “escrow-agreement,” a page that doesn’t exist. After: 41 entries and 278 links, with all nine links pointing to “buyer-form-escrow-agreement” and three new pages: index, instructions email, and escalations." loading="lazy" width="3840" height="1812" decoding="async" data-nimg="1" style="color:transparent" src="https://origin-ten-jet.vercel.app/sites/anthropic/pages-assets/167d55df42b63be22234.webp"><figcaption style="--figure-label:&quot;Figure 15&quot;" class="RMuY0W_root -LJkNq_container -LJkNq_container--default" data-component="RichTextWrapper"><div class="tOQyXa_caption-1 -LJkNq_text" data-component="Caption">The wiki before and after a second dreaming pass.</div></figcaption></figure></div><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="thinking-backward-looking-forward">Thinking backward, looking forward</h3><p class="PA4F1q_reading-column post-text">There are many open questions about how to design memory systems for agents. One is when Claude should create memory. When Claude works on a task, it can write to a memory store (e.g., a folder, file, or database), capturing salience at the source and making important details immediately available for future turns or sessions. But logging notes in the moment inevitably draws Claude’s attention away from its main task. In contrast, dreaming can push memory creation to the background, but any outputs from dreaming may not be immediately accessible to Claude.</p><p class="PA4F1q_reading-column post-text">Another question is how to keep memory reliably up to date. Claude can make incorrect predictions or write rules to memory that are wrong from the start. Memory can also drift and become irrelevant as the environment changes. Dreaming is one way to fix these mistakes (Figure 8), but it requires compute. Directing Claude to continuously check <em>all</em> its memories might not be practical. It may be important instead to focus dreaming on information that’s likely to change or to carefully tune the cadence of dreaming (e.g., based on how often memories are accessed).</p><p class="PA4F1q_reading-column post-text">It’s also reasonable to consider transcript search as the foundation of Claude’s memory. Combining representations (e.g., wikis) with search (Figure 10) can sometimes be effective. But Claude needs to use compute to maintain memory representations and make sure they don’t accumulate errors or hallucinations.</p><p class="PA4F1q_reading-column post-text">Even though Claude’s judgment about salience has improved, no model can really know what will happen in future turns. Dreaming gives Claude an opportunity to look <em>backward</em> and use compute to organize its memory, correct mistakes, and maintain representations that allow future sessions to access memory more readily. Memory systems will evolve as Claude gets more capable, and we still have a lot to learn about designing Claude’s memory systems.</p><p class="PA4F1q_reading-column post-text">See our cookbooks for <a id="base-ui-_R_faidrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://platform.claude.com/cookbook/managed-agents-cma-dreaming-with-a-dynamic-workflow">getting started with dreaming</a> and <a id="base-ui-_R_fiidrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://github.com/anthropics/claude-quickstarts/tree/main/managed-agents/knowledge-wiki">knowledge wikis</a>.</p></div></div><section class="UxquqW_Section theme-slate"><div class="Bo9kyq_container" data-component="CSSGrid.Container"><div class="Bo9kyq_standard Bo9kyq_flow-row UxquqW_Grid" data-component="CSSGrid.Standard"><div class="Bo9kyq_m-full Bo9kyq_t-span-10 Bo9kyq_t-start-2 Bo9kyq_d-span-5 Bo9kyq_d-start-1" data-component="CSSGrid.Item"><div style="visibility: visible; translate: none; rotate: none; scale: none; transform: translate3d(0px, 0px, 0px); opacity: 0.8821;"><h2 class="tOQyXa_headline-3 text-subheadline-2" data-component="Headline"><span>Authors &amp; acknowledgements</span></h2></div></div><div class="Bo9kyq_m-full Bo9kyq_t-span-10 Bo9kyq_t-start-2 Bo9kyq_d-span-7 Bo9kyq_d-start-6" data-component="CSSGrid.Item"><div class="UxquqW_Content" style="visibility: visible; translate: none; rotate: none; scale: none; transform: translate3d(0px, 0px, 0px); opacity: 0.8821;"><div class="UxquqW_Block"><h3 class="tOQyXa_headline-6 UxquqW_BlockTitle" data-component="Headline">Acknowledgements</h3><div class="UxquqW_BlockContent"><div class="RMuY0W_root RMuY0W_secondary YQKUZG_wrapper" data-component="RichTextWrapper"><p>Written by Lance Martin with editorial guidance from Caitlin Love, Tom Chivers, Rebecca Hiscott, Jake Eaton, and Blake Wilson.
