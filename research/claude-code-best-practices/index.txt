Try common workflows</h2><p class="PA4F1q_reading-column post-text">Claude Code doesn’t impose a specific workflow, giving you the flexibility to use it how you want. Within the space this flexibility affords, several successful patterns for effectively using Claude Code have emerged across our community of users:</p><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="a-explore-plan-code-commit">a. Explore, plan, code, commit</h3><p class="PA4F1q_reading-column post-text">This versatile workflow suits many problems:</p><ol class="PA4F1q_reading-column text-body-1-serif post-text"><li><strong>Ask Claude to read relevant files, images, or URLs</strong>, providing either general pointers ("read the file that handles logging") or specific filenames ("read logging.py"), but explicitly tell it not to write any code just yet.<ol class="PA4F1q_reading-column text-body-1-serif post-text"><li>This is the part of the workflow where you should consider strong use of subagents, especially for complex problems. Telling Claude to use subagents to verify details or investigate particular questions it might have, especially early on in a conversation or task, tends to preserve context availability without much downside in terms of lost efficiency.</li></ol></li><li><strong>Ask Claude to make a plan for how to approach a specific problem</strong>. We recommend using the word "think" to trigger extended thinking mode, which gives Claude additional computation time to evaluate alternatives more thoroughly. These specific phrases are mapped directly to increasing levels of thinking budget in the system: "think" &lt; "think hard" &lt; "think harder" &lt; "ultrathink." Each level allocates progressively more thinking budget for Claude to use.<ol class="PA4F1q_reading-column text-body-1-serif post-text"><li>If the results of this step seem reasonable, you can have Claude create a document or a GitHub issue with its plan so that you can reset to this spot if the implementation (step 3) isn’t what you want.</li></ol></li><li><strong>Ask Claude to implement its solution in code</strong>. This is also a good place to ask it to explicitly verify the reasonableness of its solution as it implements pieces of the solution.</li><li><strong>Ask Claude to commit the result and create a pull request</strong>. While sometimes that's what you want, asking Claude to research and plan first significantly improves performance for problems requiring deeper thinking upfront.</p><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="b-write-tests-commit-code-iterate-commit">b. Give Claude the tools to see its outputs for best results.</p><div class="PA4F1q_media-column" data-type="image"><figure class="Duq99q_e-imageWithCaption"><img alt="Safe yolo mode" loading="lazy" width="1600" height="1143" decoding="async" data-nimg="1" style="color:transparent" src="https://origin-ten-jet.vercel.app/sites/anthropic/pages-assets/1c4bb2aa57ec4418f699.webp"></figure></div><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="d-safe-yolo-mode">d. This works well for workflows like fixing lint errors or generating boilerplate code.</p><p class="PA4F1q_reading-column post-text">Letting Claude run arbitrary commands is risky and can result in data loss, system corruption, or even data exfiltration (e.g., via prompt injection attacks). To minimize these risks, use <code class="nsPAba_code">--dangerously-skip-permissions</code> in a container without internet access. You can follow this <a id="base-ui-_R_v1sdrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://github.com/anthropics/claude-code/tree/main/.devcontainer" rel="noopener noreferrer">reference implementation</a> using Docker Dev Containers.</p><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="e-codebase-qa">e. Codebase Q&amp;A</h3><p class="PA4F1q_reading-column post-text">When onboarding to a new codebase, use Claude Code for learning and exploration.  You can ask Claude the same sorts of questions you would ask another engineer on the project when pair programming. Claude can agentically search the codebase to answer general questions like:</p><ul class="PA4F1q_reading-column text-body-1-serif post-text"><li>How does logging work?</li><li>How do I make a new API endpoint?</li><li>What does <code class="nsPAba_code">async move { ... }</code> do on line 134 of <code class="nsPAba_code">foo.rs</code>?</li><li>What edge cases does <code class="nsPAba_code">CustomerOnboardingFlowImpl</code> handle?</li><li>Why are we calling <code class="nsPAba_code">foo()</code> instead of <code class="nsPAba_code">bar()</code> on line 333?</li><li>What’s the equivalent of line 334 of <code class="nsPAba_code">baz.py</code> in Java?</li></ul><p class="PA4F1q_reading-column post-text">At Anthropic, using Claude Code in this way has become our core onboarding workflow, significantly improving ramp-up time and reducing load on other engineers. No special prompting is required! Simply ask questions, and Claude will explore the code to find answers.</p><div class="PA4F1q_media-column" data-type="image"><figure class="Duq99q_e-imageWithCaption"><img alt="Use Claude to interact with git" loading="lazy" width="1600" height="1278" decoding="async" data-nimg="1" style="color:transparent" src="https://origin-ten-jet.vercel.app/sites/anthropic/pages-assets/58b344c3f6df0abbfd83.webp"></figure></div><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="f-use-claude-to-interact-with-git">f. Use Claude to interact with git</h3><p class="PA4F1q_reading-column post-text">Claude can effectively handle many git operations. Claude can interpret outputs, including images, providing a fast way to explore and interact with data. Mention files you want Claude to look at or work on</h3><p class="PA4F1q_reading-column post-text">Use tab-completion to quickly reference files or folders anywhere in your repository, helping Claude find or update the right resources.</p><div class="PA4F1q_media-column" data-type="image"><figure class="Duq99q_e-imageWithCaption"><img alt="Give Claude URLs" loading="lazy" width="1306" height="1088" decoding="async" data-nimg="1" style="color:transparent" src="https://origin-ten-jet.vercel.app/sites/anthropic/pages-assets/391896e1cd6530c05d04.webp"></figure></div><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="d-give-claude-urls">d. Give Claude URLs</h3><p class="PA4F1q_reading-column post-text">Paste specific URLs alongside your prompts for Claude to fetch and read. To avoid permission prompts for the same domains (e.g., docs.foo.com), use<em> </em><code class="nsPAba_code">/permissions</code> to add domains to your allowlist.</p><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="e-course-correct-early-and-often">e. Course correct early and often</h3><p class="PA4F1q_reading-column post-text">While auto-accept mode (shift+tab to toggle) lets Claude work autonomously, you'll typically get better results by being an active collaborator and guiding Claude's approach. You can get the best results by thoroughly explaining the task to Claude at the beginning, but you can also course correct Claude at any time.</p><p class="PA4F1q_reading-column post-text">These four tools help with course correction:</p><ul class="PA4F1q_reading-column text-body-1-serif post-text"><li><strong>Ask Claude to make a plan</strong> before coding. Explicitly tell it not to code until you’ve confirmed its plan looks good.</li><li><strong>Press Escape to interrupt</strong> Claude during any phase (thinking, tool calls, file edits), preserving context so you can redirect or expand instructions.</li><li><strong>Double-tap Escape to jump back in history</strong>, edit a previous prompt, and explore a different direction. You can edit the prompt and repeat until you get the result you're looking for.</li><li><strong>Ask Claude to undo changes</strong>, often in conjunction with option #2 to take a different approach.</li></ul><p class="PA4F1q_reading-column post-text">Though Claude Code occasionally solves problems perfectly on the first attempt, using these correction tools generally produces better solutions faster.</p><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="f-use-clear-to-keep-context-focused">f. Use <code class="nsPAba_code">/clear</code> to keep context focused</h3><p class="PA4F1q_reading-column post-text">During long sessions, Claude's context window can fill with irrelevant conversation, file contents, and commands. This can reduce performance and sometimes distract Claude. Use the <code class="nsPAba_code">/clear</code> command frequently between tasks to reset the context window.</p><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="g-use-checklists-and-scratchpads-for-complex-workflows">g. Use checklists and scratchpads for complex workflows</h3><p class="PA4F1q_reading-column post-text">For large tasks with multiple steps or requiring exhaustive solutions—like code migrations, fixing numerous lint errors, or running complex build scripts—improve performance by having Claude use a Markdown file (or even a GitHub issue!) as a checklist and working scratchpad:</p><p class="PA4F1q_reading-column post-text">For example, to fix a large number of lint issues, you can do the following:</p><ol class="PA4F1q_reading-column text-body-1-serif post-text"><li><strong>Tell Claude to run the lint command</strong> and write all resulting errors (with filenames and line numbers) to a Markdown checklist</li><li><strong>Instruct Claude to address each issue one by one</strong>, fixing and verifying before checking it off and moving to the next</li></ol><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="h-pass-data-into-claude">h. Pass data into Claude</h3><p class="PA4F1q_reading-column post-text">Several methods exist for providing data to Claude:</p><ul class="PA4F1q_reading-column text-body-1-serif post-text"><li><strong>Copy and paste</strong> directly into your prompt (most common approach)</li><li><strong>Pipe into Claude Code</strong> (e.g., <code class="nsPAba_code">cat foo.txt | claude</code>), particularly useful for logs, CSVs, and large data</li><li><strong>Tell Claude to pull data</strong> via bash commands, MCP tools, or custom slash commands</li><li><strong>Ask Claude to read files</strong> or fetch URLs (works for images too)</li></ul><p class="PA4F1q_reading-column post-text">Most sessions involve a combination of these approaches. For example, you can pipe in a log file, then tell Claude to use a tool to pull in additional context to debug the logs.</p><h2 class="tOQyXa_headline-4 PA4F1q_reading-column post-heading" data-component="Headline" id="5-use-headless-mode-to-automate-your-infra">5. Use headless mode to automate your infra</h2><p class="PA4F1q_reading-column post-text">Claude Code includes <a id="base-ui-_R_ujedrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://docs.anthropic.com/en/docs/agents-and-tools/claude-code/overview#automate-ci-and-infra-workflows" rel="noopener noreferrer">headless mode</a> for non-interactive contexts like CI, pre-commit hooks, build scripts, and automation. Use the <code class="nsPAba_code">-p</code> flag with a prompt to enable headless mode, and <code class="nsPAba_code">--output-format stream-json</code> for streaming JSON output.</p><p class="PA4F1q_reading-column post-text">Note that headless mode does not persist between sessions. You have to trigger it each session.</p><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="a-use-claude-for-issue-triage">a. Use Claude for issue triage</h3><p class="PA4F1q_reading-column post-text">Headless mode can power automations triggered by GitHub events, such as when a new issue is created in your repository. For example, the public <a id="base-ui-_R_fjhdrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://github.com/anthropics/claude-code/blob/main/.github/actions/claude-issue-triage-action/action.yml" rel="noopener noreferrer">Claude Code repository</a> uses Claude to inspect new issues as they come in and assign appropriate labels.</p><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="b-use-claude-as-a-linter">b. Use Claude as a linter</h3><p class="PA4F1q_reading-column post-text">Claude Code can provide <a id="base-ui-_R_fjjdrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://github.com/anthropics/claude-code-action/blob/main/action.yml" rel="noopener noreferrer">subjective code reviews</a> beyond what traditional linting tools detect, identifying issues like typos, stale comments, misleading function or variable names, and more.</p><h2 class="tOQyXa_headline-4 PA4F1q_reading-column post-heading" data-component="Headline" id="6-uplevel-with-multi-claude-workflows">6. Uplevel with multi-Claude workflows</h2><p class="PA4F1q_reading-column post-text">Beyond standalone usage, some of the most powerful applications involve running multiple Claude instances in parallel:</p><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="a-have-one-claude-write-code-use-another-claude-to-verify">a. Have one Claude write code; use another Claude to verify</h3><p class="PA4F1q_reading-column post-text">A simple but effective approach is to have one Claude write code while another reviews or tests it. Similar to working with multiple engineers, sometimes having separate context is beneficial:</p><ol class="PA4F1q_reading-column text-body-1-serif post-text"><li>Use Claude to write code</li><li>Run <code class="nsPAba_code">/clear</code> or start a second Claude in another terminal</li><li>Have the second Claude review the first Claude's work</li><li>Start another Claude (or <code class="nsPAba_code">/clear</code> again) to read both the code and review feedback</li><li>Have this Claude edit the code based on the feedback</li></ol><p class="PA4F1q_reading-column post-text">You can do something similar with tests: have one Claude write tests, then have another Claude write code to make the tests pass. You can even have your Claude instances communicate with each other by giving them separate working scratchpads and telling them which one to write to and which one to read from.</p><p class="PA4F1q_reading-column post-text">This separation often yields better results than having a single Claude handle everything.</p><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="b-have-multiple-checkouts-of-your-repo">b. Have multiple checkouts of your repo</h3><p class="PA4F1q_reading-column post-text">Rather than waiting for Claude to complete each step, something many engineers at Anthropic do is:</p><ol class="PA4F1q_reading-column text-body-1-serif post-text"><li><strong>Create 3-4 git checkouts</strong> in separate folders</li><li><strong>Open each folder</strong> in separate terminal tabs</li><li><strong>Start Claude in each folder </strong>with different tasks</li><li><strong>Cycle through</strong> to check progress and approve/deny permission requests</li></ol><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="c-use-git-worktrees">c. Use git worktrees</h3><p class="PA4F1q_reading-column post-text">This approach shines for multiple independent tasks, offering a lighter-weight alternative to multiple checkouts. Git worktrees allow you to check out multiple branches from the same repository into separate directories. Each worktree has its own working directory with isolated files, while sharing the same Git history and reflog.</p><p class="PA4F1q_reading-column post-text">Using git worktrees enables you to run multiple Claude sessions simultaneously on different parts of your project, each focused on its own independent task. For instance, you might have one Claude refactoring your authentication system while another builds a completely unrelated data visualization component. Since the tasks don't overlap, each Claude can work at full speed without waiting for the other's changes or dealing with merge conflicts:</p><ol class="PA4F1q_reading-column text-body-1-serif post-text"><li><strong>Create worktrees</strong>: <code class="nsPAba_code">git worktree add ../project-feature-a feature-a</code></li><li><strong>Launch Claude in each worktree</strong>: <code class="nsPAba_code">cd ../project-feature-a &amp;&amp; claude</code></li><li><strong>Create additional worktrees</strong> as needed (repeat steps 1-2 in new terminal tabs)</li></ol><p class="PA4F1q_reading-column post-text">Some tips:</p><ul class="PA4F1q_reading-column text-body-1-serif post-text"><li>Use consistent naming conventions</li><li>Maintain one terminal tab per worktree</li><li>If you’re using iTerm2 on Mac, <a id="base-ui-_R_3ss3drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://docs.anthropic.com/en/docs/agents-and-tools/claude-code/overview#notification-setup" rel="noopener noreferrer">set up notifications</a> for when Claude needs attention</li><li>Use separate IDE windows for different worktrees</li><li>Clean up when finished: <code class="nsPAba_code">git worktree remove ../project-feature-a</code></li></ul><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="d-use-headless-mode-with-a-custom-harness">d. Use headless mode with a custom harness</h3><p class="PA4F1q_reading-column post-text"><code class="nsPAba_code">claude -p</code> (headless mode) integrates Claude Code programmatically into larger workflows while leveraging its built-in tools and system prompt. There are two primary patterns for using headless mode:</p><p class="PA4F1q_reading-column post-text">1. <strong>Fanning out</strong> handles large migrations or analyses (e.g., analyzing sentiment in hundreds of logs or analyzing thousands of CSVs):</p><ol class="PA4F1q_reading-column text-body-1-serif post-text"><li>Have Claude write a script to generate a task list. For example, generate a list of 2k files that need to be migrated from framework A to framework B.</li><li>Loop through tasks, calling Claude programmatically for each and giving it a task and a set of tools it can use. For example: <code class="nsPAba_code">claude -p “migrate foo.py from React to Vue. When you are done, you MUST return the string OK if you succeeded, or FAIL if the task failed.” --allowedTools Edit Bash(git commit:*)</code></li><li>Run the script several times and refine your prompt to get the desired outcome.</li></ol><p class="PA4F1q_reading-column post-text">2. <strong>Pipelining</strong> integrates Claude into existing data/processing pipelines:</p><ol class="PA4F1q_reading-column text-body-1-serif post-text"><li>Call <code class="nsPAba_code">claude -p “&lt;your prompt&gt;” --json | your_command</code>, where <code class="nsPAba_code">your_command</code> is the next step of your processing pipeline</li><li>That’s it!
