post-text"><br>High-quality behavioral evaluations are essential for understanding alignment in frontier AI models. But evaluations generally take a long time to develop, and then run the risk of becoming obsolete: the evaluations can “contaminate” training sets for new models, or capabilities can improve to such an extent that the evaluation no longer really tests what we’re interested in. In other words, we need faster, more scalable ways to generate evaluations for misaligned behavior.</p><p class="PA4F1q_reading-column post-text">To this end, we recently released <a href="/research/petri-open-source-auditing">Petri</a>, an open-source tool that allows researchers to automatically explore AI models’ behavioral profiles through diverse multi-turn conversations with simulated users and tools. Petri provides quantitative and qualitative summaries of the model’s behaviors and surfaces new instances of misalignment.</p><p class="PA4F1q_reading-column post-text">Bloom is a complementary evaluation tool. Bloom generates targeted evaluation suites for arbitrary behavioral traits. Unlike Petri—which takes user-specified scenarios and scores many behavioral dimensions to flag concerning instances—Bloom takes a single behavior and automatically generates many scenarios to quantify how often it occurs. We built Bloom to allow researchers to quickly measure the model properties they’re interested in, without needing to spend time on evaluation pipeline engineering. Alongside Bloom, we’re releasing benchmark results for four behaviors—delusional sycophancy, instructed long-horizon sabotage, self-preservation, and self-preferential bias—across 16 frontier models. Using Bloom, these evaluations took only a few days to conceptualize, refine, and generate. Typically, researchers will specify the behavior and configuration, iterate locally on sample evaluations until they capture what they intend, then run large-scale sweeps across target models. Bloom integrates with Weights &amp; Biases for experiments at scale and exports <a id="base-ui-_R_1u6drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" href="https://inspect.aisi.org.uk">Inspect</a>-compatible transcripts. It also offers a custom transcript viewer. The repository includes a sample seed file to get started.</p><p class="PA4F1q_reading-column post-text">Bloom generates evaluations in four stages:</p><ol class="PA4F1q_reading-column text-body-1-serif post-text"><li>Understanding: The first Bloom “agent” analyzes the researcher’s behavior description and example transcripts to generate detailed context about what to measure and why.</li><li>Ideation: The ideation agent generates evaluation scenarios designed to elicit the target behavior. Each scenario specifies the situation, simulated user, system prompt, and interaction environment.</li><li>Rollout: These scenarios are rolled out in parallel, with an agent dynamically simulating both the user’s and the tool responses to elicit the sought-after behavior in the target model.</li><li>Judgment: A judge model scores each transcript for the presence of the behavior, along with other user-defined qualities, and a meta-judge produces suite-level analysis.</li></ol><div class="PA4F1q_media-column" data-type="image" data-width="inline-width"><figure class="Duq99q_e-imageWithCaption"><img alt="Diagram titled “Bloom Pipeline.” A top row shows a seed input feeding an automated pipeline, which produces a transcript viewer and top-level metrics. The pipeline expands into four stages.  Understanding: extract and generate context from the seed. Ideation: ideate n scenarios, given the settings user mode, max turns, diversity, and modality. Rollout: roll out n scenarios with m max turns each. A Bloom agent generates the target system prompt and sends the initial user message. If the modality is a simulated environment, the target model makes tool calls and receives simulated tool responses. The target model gives a conversational response. If in user mode, a simulated user responds. The loop then starts the next turn or ends the interaction. Judgment: score each rollout for behavior presence and additional qualities, on 0 to 10 scales for behavior presence, elicitation difficulty, and evaluation validity. A meta-judgment step then scores the whole suite on qualities such as diversity (also 0 to 10) and returns a report." loading="lazy" width="2293" height="1290" decoding="async" data-nimg="1" style="color:transparent" src="https://origin-ten-jet.vercel.app/sites/anthropic/pages-assets/2f6df41c5c518a64bfaa.webp"><figcaption class="RMuY0W_root -LJkNq_container -LJkNq_container--default" data-component="RichTextWrapper"><div class="tOQyXa_caption-1 -LJkNq_text" data-component="Caption">Bloom's four-stage pipeline with configurable parameters at each stage. Users provide a behavior description and seed configuration; Bloom generates rollout-level and suite-level metrics along with a descriptive report.</div></figcaption></figure></div><p class="PA4F1q_reading-column post-text">Unlike fixed evaluation sets, Bloom produces different scenarios on each run while measuring the same underlying behavior (with the option for static single-turn evaluations). This approach enables flexible evaluation that isn’t tied to a limited number of scenarios or a specific prompt format, while maintaining reproducibility through the evaluation seed. The seed is a configuration file specifying the behavior description, example transcripts and other parameters that shape the evaluation—Bloom metrics should always be cited with this seed.</p><p class="PA4F1q_reading-column post-text">Researchers can extensively configure Bloom's behavior, through choosing models for each stage, adjusting the interactions’ length and modality (i.e., whether to expose tools to the target model, whether to simulate a user), controlling how diverse the evaluation scenarios are, and specifying secondary scoring dimensions, like realism or elicitation difficulty.</p><p class="PA4F1q_reading-column post-text"><strong>Example outputs from all four stages of the Bloom evaluation pipeline can be viewed <a id="base-ui-_R_3tcdrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://claude.ai/public/artifacts/cbfddf51-ab0d-45a9-913b-163ae2dd4126" rel="noopener noreferrer">here.</a></strong></p><h2 class="tOQyXa_headline-4 PA4F1q_reading-column post-heading" data-component="Headline" id="validation-and-trust">Validation and trust</h2><p class="PA4F1q_reading-column post-text">To validate Bloom’s performance, we test it against two questions.</p><p class="PA4F1q_reading-column post-text"><strong>Can Bloom reliably distinguish models with different behavioral tendencies? </strong>To validate this, we use Bloom to evaluate production Claude models against system-prompted “model organisms” that have been intentionally designed to exhibit specific quirky behaviors (Bricken et al, 2025). Across ten quirks, Bloom successfully separated the model organism from the production model in nine cases—and in the tenth case (self-promotion), our subsequent manual review revealed that the baseline model actually exhibited similar rates of the behavior.</p><div class="PA4F1q_media-column" data-type="image" data-width="inline-width"><figure class="Duq99q_e-imageWithCaption"><img alt="Dot plot with error bars titled “Elicitation Rate: Baseline vs. Model Organism,” showing elicitation rate (%) for ten quirks. Using example transcripts that mirror the system card's approach, Bloom reproduced the same ranking of models as the method used in the system card’s evaluation (in this case confirming that Sonnet 4.5 exhibits the least bias of the models tested). Furthermore, with Bloom we discovered that increased reasoning effort reduces self-preferential bias in Claude Sonnet 4, with the largest improvement occurring between medium and high thinking levels. (Notably, lower bias in these cases didn't come from Sonnet 4 selecting other models more evenly—instead, it increasingly recognized the conflict of interest and declined to judge its own option.)</p><p class="PA4F1q_reading-column post-text">Beyond replicating known results, Bloom enables deeper investigation through secondary judgment criteria. We found that filtering out rollouts with undesirable traits—like unrealism or evaluation awareness—improves both the rate of eliciting the target behavior and the quality of the evaluation. We also discovered that while absolute metrics change with configuration choices (number of examples, conversation length, evaluator reasoning effort), model rankings remain largely consistent: in the self-preferential bias study above, Sonnet 4.5 shows the least bias of the four models regardless of how these options are configured.</p><h2 class="tOQyXa_headline-4 PA4F1q_reading-column post-heading" data-component="Headline" id="get-started">Get started</h2><p class="PA4F1q_reading-column post-text">We built Bloom to be accessible and highly configurable, serving as a reliable evaluation generation framework for diverse research applications. Early adopters are already using Bloom to evaluate nested jailbreak vulnerabilities, test hardcoding, measure evaluation awareness, and generate sabotage traces.</p><p class="PA4F1q_reading-column post-text">As AI systems grow more capable and are deployed in increasingly complex environments, the alignment research community needs scalable tools for exploring their behavioral traits. This is what Bloom is designed to facilitate.</p><p class="PA4F1q_reading-column post-text">For complete technical details, experimental configurations, additional case studies, and limitations, read our full technical report on the <a id="base-ui-_R_1updrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://alignment.anthropic.com/2025/bloom-auto-evals/" rel="noopener noreferrer">Alignment Science blog</a>.</p><p class="PA4F1q_reading-column post-text">Access Bloom at <a id="base-ui-_R_1uqdrpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://github.com/safety-research/bloom" rel="noopener noreferrer">github.com/safety-research/bloom</a>.</p></div></div><section class="UxquqW_Section theme-slate"><div class="Bo9kyq_container" data-component="CSSGrid.Container"><div class="Bo9kyq_standard Bo9kyq_flow-row UxquqW_Grid" data-component="CSSGrid.Standard"><div class="Bo9kyq_m-full Bo9kyq_t-span-10 Bo9kyq_t-start-2 Bo9kyq_d-span-5 Bo9kyq_d-start-1" data-component="CSSGrid.Item"><div style="visibility: visible; translate: none; rotate: none; scale: none; transform: translate(0px, 0px); opacity: 1;"><h2 class="tOQyXa_headline-3 text-subheadline-2" data-component="Headline"><span>Authors &amp; acknowledgements</span></h2></div></div><div class="Bo9kyq_m-full Bo9kyq_t-span-10 Bo9kyq_t-start-2 Bo9kyq_d-span-7 Bo9kyq_d-start-6" data-component="CSSGrid.Item"><div class="UxquqW_Content" style="visibility: visible; translate: none; rotate: none; scale: none; transform: translate(0px, 0px); opacity: 1;"><div class="UxquqW_Block"><h3 class="tOQyXa_headline-6 UxquqW_BlockTitle" data-component="Headline">Acknowledgements</h3><div class="UxquqW_BlockContent"><div class="RMuY0W_root RMuY0W_secondary YQKUZG_wrapper" data-component="RichTextWrapper"><p>We would like to thank Keshav Shenoy, Christine Ye, Simon Storf, Julius Steen, Jifan Zhang and Javier Rando for early feedback on Bloom.
