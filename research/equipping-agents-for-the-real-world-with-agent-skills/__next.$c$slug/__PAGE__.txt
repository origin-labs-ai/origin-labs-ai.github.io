class="PA4F1q_reading-column PA4F1q_rule"><p class="PA4F1q_reading-column post-text">As model capabilities improve, we can now build general-purpose agents that interact with full-fledged computing environments. <a id="base-ui-_R_3s3drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://claude.com/product/claude-code" rel="noopener noreferrer">Claude Code</a>, for example, can accomplish complex tasks across domains using local code execution and filesystems. But as these agents become more powerful, we need more composable, scalable, and portable ways to equip them with domain-specific expertise.</p><p class="PA4F1q_reading-column post-text">This led us to create <a href="/news/skills"><strong>Agent Skills</strong></a>: organized folders of instructions, scripts, and resources that agents can discover and load dynamically to perform better at specific tasks.<strong> </strong>Skills extend Claude’s capabilities by packaging your expertise into composable resources for Claude, transforming general-purpose agents into specialized agents that fit your needs.</p><p class="PA4F1q_reading-column post-text">Building a skill for an agent is like putting together an onboarding guide for a new hire. Instead of building fragmented, custom-designed agents for each use case, anyone can now specialize their agents with composable capabilities by capturing and sharing their procedural knowledge. In this article, we explain what Skills are, show how they work, and share best practices for building your own.</p><div class="PA4F1q_media-column" data-type="image"><figure class="Duq99q_e-imageWithCaption"><img alt="To activate skills, all you need to do is write a SKILL.md file with custom guidance for your agent." loading="lazy" width="1650" height="929" decoding="async" data-nimg="1" style="color:transparent" src="https://origin-ten-jet.vercel.app/sites/anthropic/pages-assets/adace9b292b795cddb24.webp"><figcaption class="RMuY0W_root -LJkNq_container -LJkNq_container--default" data-component="RichTextWrapper"><div class="tOQyXa_caption-1 -LJkNq_text" data-component="Caption">A skill is a directory containing a SKILL.md file that contains organized folders of instructions, scripts, and resources that give agents additional capabilities. </div></figcaption></figure></div><h2 class="tOQyXa_headline-4 PA4F1q_reading-column post-heading" data-component="Headline" id="the-anatomy-of-a-skill">The anatomy of a skill</h2><p class="PA4F1q_reading-column post-text">To see Skills in action, let’s walk through a real example: one of the skills that powers <a href="/news/create-files">Claude’s recently launched document editing abilities</a>. Claude already knows a lot about understanding PDFs, but is limited in its ability to manipulate them directly (e.g. to fill out a form). This <a id="base-ui-_R_7o8drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://github.com/anthropics/skills/tree/main/document-skills/pdf" rel="noopener noreferrer">PDF skill</a> lets us give Claude these new abilities.</p><p class="PA4F1q_reading-column post-text">At its simplest, a skill is a directory that contains a <code class="nsPAba_code">SKILL.md file</code>. This file must start with YAML frontmatter that contains some required metadata: <code class="nsPAba_code">name</code> and <code class="nsPAba_code">description</code>. At startup, the agent pre-loads the <code class="nsPAba_code">name</code> and <code class="nsPAba_code">description</code> of every installed skill into its system prompt.</p><p class="PA4F1q_reading-column post-text">This metadata is the <strong>first level</strong> of <em>progressive disclosure</em>: it provides just enough information for Claude to know when each skill should be used without loading all of it into context. The actual body of this file is the <strong>second level</strong> of detail. If Claude thinks the skill is relevant to the current task, it will load the skill by reading its full <code class="nsPAba_code">SKILL.md</code> into context.</p><div class="PA4F1q_media-column" data-type="image"><figure class="Duq99q_e-imageWithCaption"><img alt="Anatomy of a SKILL.md file including the relevant metadata: name, description, and context related to the specific actions the skill should take." loading="lazy" width="1650" height="929" decoding="async" data-nimg="1" style="color:transparent" src="https://origin-ten-jet.vercel.app/sites/anthropic/pages-assets/452b8b6759da84674a02.webp"><figcaption class="RMuY0W_root -LJkNq_container -LJkNq_container--default" data-component="RichTextWrapper"><div class="tOQyXa_caption-1 -LJkNq_text" data-component="Caption">A SKILL.md file must begin with YAML Frontmatter that contains a file name and description, which is loaded into its system prompt at startup.</div></figcaption></figure></div><p class="PA4F1q_reading-column post-text">As skills grow in complexity, they may contain too much context to fit into a single <code class="nsPAba_code">SKILL.md</code>, or context that’s relevant only in specific scenarios. In these cases, skills can bundle additional files within the skill directory and reference them by name from <code class="nsPAba_code">SKILL.md</code>. These additional linked files are the <strong>third level</strong> (and beyond) of detail, which Claude can choose to navigate and discover only as needed.</p><p class="PA4F1q_reading-column post-text">In the PDF skill shown below, the <code class="nsPAba_code">SKILL.md</code> refers to two additional files (<code class="nsPAba_code">reference.md</code> and <code class="nsPAba_code">forms.md</code>) that the skill author chooses to bundle alongside the core <code class="nsPAba_code">SKILL.md</code>. By moving the form-filling instructions to a separate file (<code class="nsPAba_code">forms.md</code>), the skill author is able to keep the core of the skill lean, trusting that Claude will read <code class="nsPAba_code">forms.md</code> only when filling out a form.</p><div class="PA4F1q_media-column" data-type="image"><figure class="Duq99q_e-imageWithCaption"><img alt="How to bundle additional content into a SKILL.md file." loading="lazy" width="1650" height="1069" decoding="async" data-nimg="1" style="color:transparent" src="https://origin-ten-jet.vercel.app/sites/anthropic/pages-assets/c148640b1aecb6901d16.webp"><figcaption class="RMuY0W_root -LJkNq_container -LJkNq_container--default" data-component="RichTextWrapper"><div class="tOQyXa_caption-1 -LJkNq_text" data-component="Caption">You can incorporate more context (via additional files) into your skill that can then be triggered by Claude based on the system prompt.</div></figcaption></figure></div><p class="PA4F1q_reading-column post-text">Progressive disclosure is the core design principle that makes Agent Skills flexible and scalable. Like a well-organized manual that starts with a table of contents, then specific chapters, and finally a detailed appendix, skills let Claude load information only as needed:</p><div class="PA4F1q_media-column" data-type="image"><figure class="Duq99q_e-imageWithCaption"><img alt="This image depicts how progressive disclosure of context in Skills." loading="lazy" width="2292" height="673" decoding="async" data-nimg="1" style="color:transparent" src="https://origin-ten-jet.vercel.app/sites/anthropic/pages-assets/440b75a04b73cc03b288.webp"></figure></div><p class="PA4F1q_reading-column post-text">Agents with a filesystem and code execution tools don’t need to read the entirety of a skill into their context window when working on a particular task. This means that the amount of context that can be bundled into a skill is effectively unbounded.</p><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="skills-and-the-context-window">Skills and the context window</h3><p class="PA4F1q_reading-column post-text">The following diagram shows how the context window changes when a skill is triggered by a user’s message.</p><div class="PA4F1q_media-column" data-type="image"><figure class="Duq99q_e-imageWithCaption"><img alt="This image depicts how skills are triggered in your context window." loading="lazy" width="1650" height="929" decoding="async" data-nimg="1" style="color:transparent" src="https://origin-ten-jet.vercel.app/sites/anthropic/pages-assets/624ee7e0b77cc9eb0786.webp"><figcaption class="RMuY0W_root -LJkNq_container -LJkNq_container--default" data-component="RichTextWrapper"><div class="tOQyXa_caption-1 -LJkNq_text" data-component="Caption">Skills are triggered in the context window via your system prompt. </div></figcaption></figure></div><p class="PA4F1q_reading-column post-text">The sequence of operations shown:</p><ol class="PA4F1q_reading-column text-body-1-serif post-text"><li>To start, the context window has the core system prompt and the metadata for each of the installed skills, along with the user’s initial message;</li><li>Claude triggers the PDF skill by invoking a Bash tool to read the contents of <code class="nsPAba_code">pdf/SKILL.md</code>;</li><li>Claude chooses to read the <code class="nsPAba_code">forms.md</code> file bundled with the skill;</li><li>Finally, Claude proceeds with the user’s task now that it has loaded relevant instructions from the PDF skill.</li></ol><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="skills-and-code-execution">Skills and code execution</h3><p class="PA4F1q_reading-column post-text">Skills can also include code for Claude to execute as tools at its discretion.</p><p class="PA4F1q_reading-column post-text">Large language models excel at many tasks, but certain operations are better suited for traditional code execution. For example, sorting a list via token generation is far more expensive than simply running a sorting algorithm. Beyond efficiency concerns, many applications require the deterministic reliability that only code can provide.</p><p class="PA4F1q_reading-column post-text">In our example, the PDF skill includes a pre-written Python script that reads a PDF and extracts all form fields. Claude can run this script without loading either the script or the PDF into context. And because code is deterministic, this workflow is consistent and repeatable.</p><div class="PA4F1q_media-column" data-type="image"><figure class="Duq99q_e-imageWithCaption"><img alt="This image depicts how code is executed via Skills." loading="lazy" width="1650" height="929" decoding="async" data-nimg="1" style="color:transparent" src="https://origin-ten-jet.vercel.app/sites/anthropic/pages-assets/2bd05148431f3a89ac06.webp"><figcaption class="RMuY0W_root -LJkNq_container -LJkNq_container--default" data-component="RichTextWrapper"><div class="tOQyXa_caption-1 -LJkNq_text" data-component="Caption">Skills can also include code for Claude to execute as tools at its discretion based on the nature of the task.</div></figcaption></figure></div><h2 class="tOQyXa_headline-4 PA4F1q_reading-column post-heading" data-component="Headline" id="developing-and-evaluating-skills">Developing and evaluating skills</h2><p class="PA4F1q_reading-column post-text">Here are some helpful guidelines for getting started with authoring and testing skills:</p><ul class="PA4F1q_reading-column text-body-1-serif post-text"><li><strong>Start with evaluation:</strong> Identify specific gaps in your agents’ capabilities by running them on representative tasks and observing where they struggle or require additional context. Then build skills incrementally to address these shortcomings.</li><li><strong>Structure for scale: </strong>When the <code class="nsPAba_code">SKILL.md</code> file becomes unwieldy, split its content into separate files and reference them. If certain contexts are mutually exclusive or rarely used together, keeping the paths separate will reduce the token usage. Finally, code can serve as both executable tools and as documentation. It should be clear whether Claude should run scripts directly or read them into context as reference.</li><li><strong>Think from Claude’s perspective:</strong> Monitor how Claude uses your skill in real scenarios and iterate based on observations: watch for unexpected trajectories or overreliance on certain contexts. Pay special attention to the <code class="nsPAba_code">name</code> and <code class="nsPAba_code">description</code> of your skill. Claude will use these when deciding whether to trigger the skill in response to its current task.</li><li><strong>Iterate with Claude:</strong> As you work on a task with Claude, ask Claude to capture its successful approaches and common mistakes into reusable context and code within a skill. If it goes off track when using a skill to complete a task, ask it to self-reflect on what went wrong. This process will help you discover what context Claude actually needs, instead of trying to anticipate it upfront.</li></ul><h3 class="tOQyXa_headline-5 PA4F1q_reading-column post-section" data-component="Headline" id="security-considerations-when-using-skills">Security considerations when using Skills</h3><p class="PA4F1q_reading-column post-text">Skills provide Claude with new capabilities through instructions and code. While this makes them powerful, it also means that malicious skills may introduce vulnerabilities in the environment where they’re used or direct Claude to exfiltrate data and take unintended actions.</p><p class="PA4F1q_reading-column post-text">We recommend installing skills only from trusted sources. When installing a skill from a less-trusted source, thoroughly audit it before use. Start by reading the contents of the files bundled in the skill to understand what it does, paying particular attention to code dependencies and bundled resources like images or scripts. Similarly, pay attention to instructions or code within the skill that instruct Claude to connect to potentially untrusted external network sources.</p><h2 class="tOQyXa_headline-4 PA4F1q_reading-column post-heading" data-component="Headline" id="the-future-of-skills">The future of Skills</h2><p class="PA4F1q_reading-column post-text">Agent Skills are <a href="/news/skills">supported today</a> across <a id="base-ui-_R_7p3drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="http://claude.ai" rel="noopener noreferrer">Claude.ai</a>, Claude Code, the Claude Agent SDK, and the Claude Developer Platform.</p><p class="PA4F1q_reading-column post-text">In the coming weeks, we’ll continue to add features that support the full lifecycle of creating, editing, discovering, sharing, and using Skills. We’re especially excited about the opportunity for Skills to help organizations and individuals share their context and workflows with Claude. We’ll also explore how Skills can complement <a id="base-ui-_R_3t4drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://modelcontextprotocol.io/" rel="noopener noreferrer">Model Context Protocol</a> (MCP) servers by teaching agents more complex workflows that involve external tools and software.</p><p class="PA4F1q_reading-column post-text">Looking further ahead, we hope to enable agents to create, edit, and evaluate Skills on their own, letting them codify their own patterns of behavior into reusable capabilities.</p><p class="PA4F1q_reading-column post-text">Skills are a simple concept with a correspondingly simple format. This simplicity makes it easier for organizations, developers, and end users to build customized agents and give them new capabilities. </p><p class="PA4F1q_reading-column post-text">We’re excited to see what people build with Skills. Get started today by checking out our Skills <a id="base-ui-_R_7l7drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://docs.claude.com/en/docs/agents-and-tools/agent-skills/overview" rel="noopener noreferrer">docs</a> and <a id="base-ui-_R_7p7drpbsnpfkq6btb_" data-base-ui-tooltip-trigger="" target="_blank" href="https://github.com/anthropics/claude-cookbooks/tree/main/skills" rel="noopener noreferrer">cookbook</a>.</p></div></div><section class="UxquqW_Section theme-slate"><div class="Bo9kyq_container" data-component="CSSGrid.Container"><div class="Bo9kyq_standard Bo9kyq_flow-row UxquqW_Grid" data-component="CSSGrid.Standard"><div class="Bo9kyq_m-full Bo9kyq_t-span-10 Bo9kyq_t-start-2 Bo9kyq_d-span-5 Bo9kyq_d-start-1" data-component="CSSGrid.Item"><div style="visibility: visible; translate: none; rotate: none; scale: none; transform: translate3d(0px, 0px, 0px); opacity: 0.9207;"><h2 class="tOQyXa_headline-3 text-subheadline-2" data-component="Headline"><span>Authors &amp; acknowledgements</span></h2></div></div><div class="Bo9kyq_m-full Bo9kyq_t-span-10 Bo9kyq_t-start-2 Bo9kyq_d-span-7 Bo9kyq_d-start-6" data-component="CSSGrid.Item"><div class="UxquqW_Content" style="visibility: visible; translate: none; rotate: none; scale: none; transform: translate3d(0px, 0px, 0px); opacity: 0.9207;"><div class="UxquqW_Block"><h3 class="tOQyXa_headline-6 UxquqW_BlockTitle" data-component="Headline">Acknowledgements</h3><div class="UxquqW_BlockContent"><div class="RMuY0W_root RMuY0W_secondary YQKUZG_wrapper" data-component="RichTextWrapper"><p>Written by Barry Zhang, Keith Lazuka, and Mahesh Murag, who all really like folders.
